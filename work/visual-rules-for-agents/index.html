Visual rules an AI agent can follow

An agent can't interpret “make it feel premium”, so each aesthetic decision in the spec is a named rule with a token behind it. These are three of them.

Short read, 3 minutes

Role
Product owner, designer and front-end lead
Scope
The visual language of a spec for 60+ products
Timeline
Spec work from Jul 2026

Two themes from one set of tokens

Dark is the signature theme. Light is the working surface. The same tokens drive both, so an agent never picks colours for a theme. It picks a role, and the theme supplies the value.

Radius by role

Components reference a role, never a raw value, so one edit changes every card's corner. A modal, a surface, a control and a pill each get their own radius, so hierarchy shows in the corners.

AI disclosure, designed for regulation

The AI disclosure badge is the one component unique to this spec. I framed it as a legal disclosure first, so it is persistent and can't be dismissed. I scoped it first to AI built into products, such as automatic categorisation, AI-suggested values and actions taken on the user's behalf, rather than to chatbots.

  • Always visible, never dismissible
  • Always labelled in text, never colour alone

Brand against legibility

The gradient is a brand device, but the badge has to stay legible and can never rely on colour alone. Accessibility settled it. The text label carries the meaning, the gradient is decoration hidden from assistive technology, and a badge that relied on colour alone would fail WCAG 1.4.1.

Three options

Option A, chosen

Gradient on the border and dot only

The label sits in the text colour on a neutral fill, so no text ever sits on the gradient.

Option B

Gradient fill with dark text

It passed AA at both ends of the gradient, but the worst case was about 4.72:1 at the pink end, a thin margin. The gate can't check text over a gradient either, so this option looks worse now than it did then.

Option C

Gradient fill with white text

It fails contrast at the light teal end.

One state, two variants

The badge has a single state. It is static and persistent, with no hover, focus or dismiss state, and it isn't interactive unless a variant adds an info control, which then follows the button or tooltip rules.

It comes as an inline badge or as a region marker, which is linked to its region with aria-describedby. Each comes in compact and standard sizes. An optional slow gradient animation, about 4 seconds long, is the one exception to the duration tokens, and it falls back to a static gradient when reduced motion is set.

Building from the spec found one problem. An agent emitted the primitive radius token instead of the role, so I renamed the role to pill. The gate also can't see the duration exception yet, and that is logged as an open issue.

What it covers under the EU AI Act

Article 50 applies from 2 August 2026. I scoped the badge to the human-facing disclosure in Article 50(1) and 50(4). Machine-readable marking under Article 50(2), such as watermarks, signed metadata and provenance records, sits outside the design system. The spec says so, so nobody oversells the badge as full compliance.

The European Commission now publishes guidance and an icon page for labelling AI-generated content. I haven't yet checked whether the badge's glyph should match it.
